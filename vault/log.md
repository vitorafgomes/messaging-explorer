## [2026-11-12] fix | The web app no longer acts on more, or on something else, than the user selected
The entity selection is cleared whenever the connection changes, and a late response cannot overwrite a newer selection. A delete asks for the whole entity only when the selection equals the entity's count and no filter is active; the stored "all selected" flag is gone and a change of filter clears the selection. Retry and the continuous resubmit never resend a possible duplicate, which the results dialog now labels as such. The purge confirmation names the entity, its topic, the connection and the count, and requires the acknowledgement. A shortcut does nothing under another dialog. Web tests 540 to 564. Left open: the API has no field for a possible duplicate, so the web app matches the text. [[pages/services/web-app]], [[pages/roadmap/code-audit-2026-11]]

## [2026-11-12] fix | Entity names are encoded in every API path
Names of queues, topics, subscriptions and sessions went into URLs raw, so purging a queue named `orders#1` deleted the queue `orders`, and deleting a queue named `a/messages` purged the queue `a`. In the web app every value now goes through one tagged-template helper that encodes it once and throws on a missing value. On the server a resource filter decodes each name once from the raw request, because Kestrel leaves `%2F` encoded and decodes `%25`, so the routed value alone cannot tell `a%2Fb` from `a%252Fb`. Api tests 28 to 49 on a real Kestrel, web tests 519 to 540. One gap recorded: a name that is exactly `.` or `..`. [[pages/services/web-app]], [[pages/services/api]]

## [2026-11-12] fix | One exception handler, one 500 body, and the boundary guards seen firing
An exception handler outermost in the pipeline answers `{ "message": "An internal error occurred." }` in every environment. It closed a leak nobody had recorded: in Development the developer exception page echoed the request headers, the API key among them. The queue, topic and session controllers now use the same body as the rest, and the import action no longer returns an exception's message. Two guards are pinned by tests: a foreign `Host` is refused, which also settles that the list in `Program.cs` is the one in effect, and the API process exits with code 1 without a 32-character `API_SECRET`. Api tests 18 to 28. [[pages/services/api]], [[pages/invariants/local-authenticated-api]]

## [2026-11-12] integrate | Code audit, November 2026
Five readers read the Azure provider, the RabbitMQ provider, the API and the two halves of the web app line by line, without running anything, and reported about 118 findings, 17 of them P1 ([[pages/roadmap/code-audit-2026-11]]). The roots that recur: entity names put in URLs unencoded, so a purge or a delete can reach another queue; a selection that survives a connection switch; "all selected" meaning the loaded page; a retry that resends possible duplicates; a RabbitMQ provider whose bulk operations cannot be made safe over the management API. The founding survey's claim that `clear-all-data` has no consumer was wrong and is corrected on the two service pages. Nothing was fixed by the audit.

## [2026-11-12] fix | Clear-all recovers an unreadable workspace and goes through the workspace manager
Making an unreadable `workspace.json` an error had left `clear-all` answering 500, because it read the counts first. The reset is now `ClearAllAsync` on the workspace manager: under its lock, through the atomic save, with counts of zero when the file cannot be read. The controller no longer builds the data path or writes the file. Core tests 65 to 70, Api 17 to 18. [[pages/services/api]], [[pages/services/core]]
