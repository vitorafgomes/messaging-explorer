Where each old menu item went

Design, not built

Today's native menu has File, View and Help. Every item gets a place in the app or is left to the system; the shortcuts are handled by the page, with Cmd on macOS and Ctrl elsewhere.

Old menu item New place Shortcut on macOS Shortcut on Windows and Linux
File, Connection
Opens the Connections screen		 Connections, the first link of the toolbar. A new connection starts from Add Connection on that screen. CmdN CtrlN
File, Clear All Data (Testing)
Today with Ctrl or Cmd, Shift, Delete		 Settings, Data, danger zone: "Clear all data", behind a typed confirmation. None: the shortcut is removed None: the shortcut is removed
File, Exit
Today a second Quit on macOS		 macOS: Quit in the application menu, the only one. Windows and Linux: Quit in the tray menu; closing the window hides it, as today. CmdQ None in the page: Alt F4 belongs to the system and closes the window
View, Toggle Developer Tools
Today F12, in development builds only		 Settings, Developer: "Open developer tools". CmdOptionI CtrlShiftI
View, Developer Mode
Today the page listens for Ctrl only		 Settings, Developer: "Developer mode". CmdShiftD CtrlShiftD
View, Toggle Full Screen
Today F11 on every system		 No item in the app. macOS: the zoom button of the title bar and the system shortcut. Windows and Linux: F11, handled by the shell. CtrlCmdF F11
Help, About Messaging Explorer
Today a native message box		 Settings, About: version, licence and links. On macOS the application menu keeps its own About item. None None

Copy, cut, paste, undo, redo and select all: from the Edit menu of the system menu bar on macOS, where the keyboard shortcuts depend on it; from the system itself on Windows and Linux, where no application menu is set.
