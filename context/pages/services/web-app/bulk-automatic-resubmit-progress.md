# Web App: Automatic resubmit, count, progress and where a run shows

The run itself, its batches, filter, pause, stop and a change of connection are on [[pages/services/web-app/bulk-automatic-resubmit]]; the dialog is on [[pages/services/web-app/bulk-automatic-resubmit-dialog]].

- **The count before a run.** `web-app/src/app/core/services/resubmit-run.service.ts#countMatching` peeks the dead-letter queue onward from position 0, 500 at a time, without bodies unless a text filter is set, applies the run's filter and publishes after each peek; it never receives, resubmits or changes anything. It ends on an empty peek or at its cap of 100,000 messages, and then says it was capped; unsubscribing aborts the peek in flight, and a failed peek ends it with the error, never with a number. It reads only where the provider reads from a position.
- **Batch numbers.** Each peek is a batch; the progress keeps the batch read last and the batches a run of N takes (`web-app/src/app/core/services/resubmit-run.service.ts#batches`), every message left behind keeps the batch that read it, and the report counts the cycles.
- **Progress and report.** Read of N, matched so far, left by the filter, resubmitted, failed, possible duplicates, elapsed, the rate over the last 5 minutes and the time left from N, computed when a batch is read or answered, with no timer (`web-app/src/app/core/services/resubmit-run.service.ts#publish`). The report (`web-app/src/app/core/services/resubmit-run.service.ts#report`) gives the totals, the counts per dead-letter reason and every failed and possible-duplicate sequence number; the screen shows the first 100, its rows kept by sequence number while the run goes on (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#ContinuousResubmitDialogComponent`), and "Save report, JSON" downloads all of them through `MessageExportService.downloadFile` (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#saveReport`). "Retry the N failed" starts a run on exactly the failed sequence numbers, without peeking and without the possible duplicates (`web-app/src/app/core/services/resubmit-run.service.ts#retry`, `web-app/src/app/core/services/resubmit-run.service.ts#retryList`). Every state of the dialog says "This operation is at-least-once: a message sent but not removed from the dead-letter queue may be delivered twice." (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#AT_LEAST_ONCE`).
- **Where it shows.** On the Notifications bell, since 2026-11-14 as the AutoResubmit artboard draws it: while a run is running or paused the bell carries a spinner and the percent read of a single run (the count of runs when there are more), is named "Notifications: resubmit running on orders, 480,000 of 700,000" (`web-app/src/app/app.ts#notificationsLabel`, `web-app/src/app/features/messages/resubmit-run-indicator.component.ts#runSummary`), and opens a menu with a card per run; with no active run the bell is the dead-letter bell it was. The card reads "Resubmit running: R of N", "Dead-letter of orders, back to the queue. Production, {connection}." (the connection alone when its group has no environment; `web-app/src/app/features/messages/resubmit-run-indicator.component.ts#where`), a bar, "About T left. L left behind, D of them possible duplicates." and Open, Pause and Stop (`web-app/src/app/features/messages/resubmit-run-indicator.component.ts#leftLine`, `web-app/src/app/features/messages/resubmit-run-indicator.component.ts#open`). The environment is the active connection's, read by `web-app/src/app/app.ts#environment`: a change of connection stops every active run, so an active run is always on the active connection. The separate run button beside the bell is gone. The queue and subscription panels show, while their entity has an active run, a spinner, "Resubmit running: R of N" with grouped numbers, "Open run" and Stop (`web-app/src/app/features/entities/entity-details.component.ts#autoResubmitRun`); the tree shows a spinner beside the dead-letter count of an entity with an active run (`web-app/src/app/features/entities/entities-tree.component.ts#resubmitRunning`). Pause and Stop on the bell's card and Stop on the panel call the run's own `pause()` and `stop()`, the path of the dialog's buttons: a resubmit in flight is aborted and its messages are reported as possible duplicates. The dialog moved to Angular Material and theme tokens.
