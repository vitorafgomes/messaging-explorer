# Web App: The entities screen as the Main artboard draws it

One topic of [[pages/services/web-app|Web App]], beside [[pages/services/web-app/features-entities-panel-and-definitions]].

- Tree. The tree pane opens on a filter field, "Filter by name" (named "Filter entities by name"), beside Refresh entities and, when the API declares supportsDefinitions, Export and Import definitions (`web-app/src/app/features/entities/entities-tree.component.ts#filter`). A row is shown when its name holds the text, in any case; a topic that matches keeps all its subscriptions, and a subscription that matches brings its topic (`web-app/src/app/features/entities/entities-tree.component.ts#shownChildren`, #shown). When the filter hides rows, a polite live notice says "N of M entities hidden by the filter" (#hiddenCount, #entityCount). Queues and Topics are h2 section heads with their count and their create button, never collapsed; each queue, topic and subscription is one button that carries aria-current="true" when selected; a topic starts closed: a click selects it and opens its subscriptions, indented 24 px, and a second click hides them (`aria-expanded` on the topic row); the filter and a selected subscription keep it open (`web-app/src/app/features/entities/entities-tree.component.ts#isExpanded`). Opening a topic listed without subscriptions (emulator counts zero) reads them (`web-app/src/app/core/services/tree-data-builder.service.ts#loadSubscriptions`); a failed read is shown and retried on reopening (`web-app/src/app/features/entities/entities-tree.component.ts#subscriptionsFailed`); an open topic re-reads after Refresh. Its row carries no count and no pattern chip. The active and dead-letter badges say their count to assistive technology (", 1,204 active messages", ", 37 dead-letter messages"); the dead-letter badge uses --app-warning-container. Since 2026-11-14 a queue or topic whose status is Disabled, SendDisabled or ReceiveDisabled shows a marker whose tooltip and name say what it cannot do, and a queue with a forward target shows a forward marker whose tooltip is "Forwards every message to <target>"; any other status, an empty one or a RabbitMQ one, shows none (`web-app/src/app/features/entities/entities-tree.component.ts#STATUS_MARKERS`, #statusMarker, #forwardMarker). Subscriptions have no marker yet: their list carries no status.
- Form errors (2026-11-15). An error line grows with its text; a summary beside Save lists each error and focuses its field (`web-app/src/app/features/entities/entity-form-dialog.component.ts#fieldErrors`).
- Panel header. The kind line of a subscription is "Subscription in topic <topic>", the topic a button that selects the topic with the node id the tree builds (`web-app/src/app/features/entities/entity-details.component.ts#openTopic`). The status is a chip beside the name, named "Status: <status>. Change status", that opens the status dialog; there is no separate Status button (`web-app/src/app/features/entities/entity-admin-actions.component.ts#part`). The actions are, in order: a queue View messages, Send; a subscription View messages, Send to topic, which sends to the subscription's topic (`web-app/src/app/features/entities/entity-details.component.ts#sendMessage`); a topic Send, Create subscription (`web-app/src/app/features/entities/entity-details.component.ts#create`); then Edit and More actions.
- More actions. A queue: Import messages; Resubmit dead-letter with its count, disabled at 0, which only opens the automatic resubmit dialog; then under "Cannot be undone", each with the trash icon in the error colour: Purge active messages, Purge dead-letter (now offered for a queue too, through the same confirmation as the other purges, DELETE queues/{name}/deadletter) and Delete queue. A subscription: the same minus Import messages; "Purge all" is gone. A topic: Delete topic. Delete is offered only when the API declares supportsEntityUpdate.
- Delete. `web-app/src/app/features/entities/entity-details.component.ts#deleteEntity` asks through the same ConfirmDialogComponent as a purge, confirmed by typing the entity name: "Delete <kind> <name>?", "This deletes <kind> "<name>" (of topic "<topic>") on <connection> with its N messages now / when the <kind> was loaded" (for a topic, "with its N subscriptions and their messages"), "It cannot be undone." Nothing is called before the confirmation. On success it clears the selection and reloads the tree; on a refusal it keeps the selection and says "Could not delete the <kind> <name>: <API message>". Calls: QueueService#deleteQueue, TopicService#deleteTopic, TopicService#deleteSubscription, all through ApiService.
- Cards. Active, Dead-letter (with "Auto resubmit" above zero, the card in --app-warning-container), Scheduled (queue), Transfer ("Waiting to be forwarded") and Transfer dead-letter whenever the API declares supportsAutoForwarding, at 0 too, Size with "Max Size 1,024 MB" (`web-app/src/app/features/entities/entity-details.component.ts#megabytes`, also used by the Max Size property of a queue and a topic). Since 2026-11-15 the subscription panel carries no standing resubmit notice: the messages dialog says, above Resubmit, on the dead-letter and transfer dead-letter tabs of a subscription, where a row or the detail pane can resubmit, "Resubmit publishes to the topic <topic>. Every subscription of <topic> receives these messages again, not only <subscription>." (`web-app/src/app/features/messages/view-messages-dialog.component.ts#topic-resubmit-note`), and the automatic resubmit of a subscription says the same (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#topic-resubmit-note`). The subscription's Active card is still the live transfer monitor.
- Tabs. A subscription: Properties, Sessions when it holds sessions, "Rules (n)" with the count last read; "Rules" when the rules could not be read (`web-app/src/app/features/entities/entity-details.component.ts#rulesLabel`, fed by `web-app/src/app/features/entities/subscription-rules.component.ts#rulesRead`). A topic opens on "Subscriptions (n)": a table Subscription (a button that selects it with the tree's node id, #openSubscription) / Active / Dead-letter (a warning badge above zero); then Properties.
- Empty and loading. With nothing selected and supportsEntityUpdate, the empty state offers Create queue (tonal) and Create topic (text). While loading, four card placeholders and three text lines are drawn, hidden from assistive technology.
- Rules tab (subscription-rules.component.ts). Add rule is a small outlined button in the bar, shown only when the list has rules; an empty list shows its icon, the heading "No rule: this subscription receives no message", "Messages published to <topic> are not kept for it until a rule is added." and a tonal Add rule. Rules that could not be read show the heading "Could not read the rules", "The API did not answer. Nothing was changed by reading. The rules of <subscription> are not shown because they were not read; the subscription may well have some." and an outlined Retry with its icon.
- Pinned by `web-app/src/app/features/entities/entity-details.component.spec.ts#EntityDetailsComponent: one panel shape for a queue and a subscription`, `web-app/src/app/features/entities/entities-tree.component.spec.ts#EntitiesTreeComponent: the tree on Material`, `web-app/src/app/features/entities/entity-details.component.spec.ts#a subscription's Active card reads`, `web-app/src/app/features/entities/transfer-monitor.component.spec.ts#reads the subscription every 3 seconds` and the end-to-end flows that open a queue and a subscription.

Not built from the artboard, with the reason: the kind and name above the loading state (the selection keeps the previous entity while loading), a subscription's Size card (Azure gives a subscription no size; see [[pages/services/core/azure-provider]]), the Export and Import definitions buttons, which stay in the tree head as their only entry point, the error text that says nothing on the broker changed (an existing spec forbids it), and nothing more of Sessions: since 2026-11-14 Main draws the Sessions and Rules tabs as Monitoring.dc.html and Rules.dc.html do. The plain Active card of a subscription is built since 2026-11-14, its count still read every 3 seconds.

**Namespace facts (2026-11-14).** Under the counts line of the empty state, when the API declares `supportsNamespaceProperties`, `NamespacePropertiesComponent` reads `GET namespace/properties` through `DefinitionsService#properties` and `ApiService`, once when shown; leaving the empty state unsubscribes, which cancels the request (`web-app/src/app/features/entities/namespace-properties.component.ts#NamespacePropertiesComponent`). It lists Tier, Messaging units (Premium), Geo-DR alias (when set), Created (UTC) and Max message size, "256 KB" or, on Premium, "Up to 100 MB, set on each queue and topic". While reading it says "Reading the namespace properties". A failed read shows, as an alert, "The namespace properties could not be read. Reading them needs the Manage right on the namespace." and only "Max message size: 256 KB, the default limit: the tier could not be read", from the provider's capabilities, never a tier it did not read (`web-app/src/app/features/entities/namespace-properties.component.ts#facts`). A provider that does not declare them shows "No namespace properties: <provider> does not declare them." (`web-app/src/app/features/entities/entity-details.component.ts#EntityDetailsComponent`). No artboard draws a namespace panel; the list follows the facts list of `web-app/src/app/shared/confirm-dialog.component.ts#ConfirmDialogComponent`, theme tokens only. Pinned by `web-app/src/app/features/entities/namespace-properties.component.spec.ts#a read that fails says the properties could not be read and that the read needs the Manage right, and shows no made-up tier` and the empty-state specs of `web-app/src/app/features/entities/entity-details.component.spec.ts#EntityDetailsComponent as Main.dc.html draws the panel`.

Since 2026-11-14 a topic's Subscriptions table has a Status column and, where the provider has rules, a Rules column with "Not counted" where the API did not count them (`web-app/src/app/features/entities/entity-details.component.ts#subscriptionColumns`), and the empty state says what the connection holds, "<target> holds N queues and N topics with N subscriptions.", from the tree built last (`web-app/src/app/core/services/tree-data-builder.service.ts#loadedCounts`).

**Cancel scheduled messages of a topic (2026-11-14).** The topic's More actions holds "Cancel scheduled messages" under "Cannot be undone" in the error colour, where the provider has scheduled messages (`web-app/src/app/features/entities/entity-details.component.ts#cancelTopicScheduled`). It asks for the sequence numbers and says the app does not list a topic's scheduled messages yet (`web-app/src/app/features/entities/topic-cancel-scheduled-dialog.component.ts#TopicCancelScheduledDialogComponent`), confirms through the queue's dialog naming the topic (`web-app/src/app/features/messages/cancel-scheduled-dialog.component.ts#CancelScheduledDialogComponent`), and shows the result per number. A scheduled send shows its sequence number until closed (`web-app/src/app/features/messages/send-message-dialog.component.ts#send`).
