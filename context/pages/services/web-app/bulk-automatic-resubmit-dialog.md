# Web App: The automatic resubmit dialog

One topic of [[pages/services/web-app|Web App]]; the run itself is on [[pages/services/web-app/bulk-automatic-resubmit]].

The run, its order, bounds, pause, stop and possible duplicates are unchanged; only the dialog changed (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#onlyMatching`).
- Configure: "Which messages" offers "All N dead-letter messages" or "Only the messages that match", and only the second passes the filter to the run; the batch hint says the cycles a run of all takes (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#batchHint`) and Start reads "Start: resubmit N" (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#startLabel`), N being the count the dialog opened with.
- Running and finished: headings "Resubmit running" and "Resubmit finished"; Read, Resubmitted, "Failed, not sent", "Possible duplicate", and "Matched so far" with a filter; "N of T read" and the percent above the bar; the left-behind list newest first while running and lowest first after (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#leftBehind`); a Total row in the reasons (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#byReason`); "Save report, CSV" with one quoted line per message left behind and a cell starting with =, +, - or @ prefixed (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#saveReportCsv`); Stop and Close tonal.
- The head-of-queue loop: the title with its icon, the intro, "Batch Size" and its hints, the "Approximately N dead letter messages in queue." notice, what the run costs, "Overall Progress N%", a status box toned by outcome, the visible "Batch Log", and "What you can do next" naming each failed and possibly duplicated sequence number (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#cycles`).
- The dead-letter reason (2026-11-14) is a select: "Any reason", MaxDeliveryCountExceeded, TTLExpiredException and HeaderSizeExceeded as the artboard draws them, and "Other", which opens an "Other reason" field for any reason a broker wrote; the run still keeps a message whose reason equals the one chosen, and Start and Count stay disabled while Other has nothing typed, which would otherwise take every reason (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#chooseReason`, `web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#reasonGiven`). The artboard's "(what the app does today)" beside Stop at the first failure is the designer's note about the old app and is not shown.
- The proposed panels (2026-11-14). Configure: with "Only the messages that match", "Enqueued from" and "Enqueued to" (`datetime-local`, read as local time) beside the reason and the text, and "Enqueued to is before Enqueued from." keeps Start and Count disabled (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#datesValid`); "Count" peeks the dead-letter queue and shows "N of M match" with how it was counted and "Nothing was changed.", then "Count again"; a count that reached its cap says "N of the first M match" and "the rest was not read"; a failed count shows the error, never a number; a change to any filter field cancels the count in flight and drops it (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#filterChanged`, `web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#countNote`). Only a finished, uncapped count names the batch hint ("1 cycle for 4, 3 of them matching") and Start ("Start: resubmit 3") (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#exactCount`). The drawn hint "1,225 cycles for 612,400" is not followed: a filtered run peeks the whole queue, so the cycles are counted on the messages read, as the run's own "Batch 961 of 1,400" draws them.
- Running: the status reads "Batch N of M: resubmitting K. Reading onward from sequence number S; the L left behind are not read again by this run." (`web-app/src/app/core/services/resubmit-run.service.ts#inFlight`); the left-behind table shows Sequence Number, Batch and Result while running and Sequence Number, Reason and Result once finished (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#runningColumns`); the rate says "last 5 minutes" once the run is 5 minutes old and "since the start" before. With a filter, "Left by the filter" stands beside "Matched so far".
- Finished: the report line "N cycles in 3 h 53 min 20 s, R messages per second on average. Started <date and time>, finished <time>." (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#finishFormat`, `web-app/src/app/core/services/resubmit-run.service.ts#formatDuration`).
- The head-of-queue loop: Elapsed and Rate once a batch was done (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#loopElapsedMs`), and after a stop on a failure "View dead-letter messages" opens the messages dialog on the dead-letter tab, loaded on demand (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#viewDeadLetter`).
- "Send with a new message ID" (2026-11-14): on configure when the opener knows the target detects duplicates, and beside "Retry the N failed" when the run's failures include a duplicate refusal (`web-app/src/app/features/messages/continuous-resubmit-dialog.component.ts#refusedAsDuplicate`); [[pages/services/web-app/bulk-new-message-id]].
- Not followed, because the words would be false: "(what the app does today)" after Stop at the first failure (the run's default is Skip), and "Pause and Stop take effect when the batch in flight has finished" (Stop aborts the request in flight and reports its messages as possible duplicates). The at-least-once sentence stays in every state.
- The head-of-queue loop, which only a provider without a read from a position reaches (RabbitMQ today), says what it guarantees since 2026-11-15: each message is sent first and removed only once the broker confirmed it, a failed batch call has an unknown outcome and a message can arrive twice, so read the dead-letter queue again before a retry. The report's CSV prefixes a cell starting with =, +, -, @, a tab or a carriage return.
