# Web App: Entity panel, tree and definitions

One topic of [[pages/services/web-app|Web App]]; the map lists the others.

## features/

**The main screen on Material (2026-11-13),** the tree and the entity panel, drawn from the artboard `context/prototypes/web-app/Main.dc.html`: Material components and theme tokens, no Bootstrap class, Font Awesome icon or literal colour left in `entity-details`, `entities-tree`, `entities-container` and `transfer-monitor`, the styles in their own `.scss` files.
- **One panel shape for a queue and a subscription** (rule 7 of [[pages/conventions/ui]]): the header, the actions, the More menu with its purges, Delete and Resubmit dead-letter, Send to topic and the tabs are as the Main artboard draws them, on [[pages/services/web-app/features-entities-main]].
- **The same cards** (Active, "Active", the count and "Open the active messages" for a queue and a subscription alike since 2026-11-14, a subscription's count read every 3 seconds by `web-app/src/app/features/entities/transfer-monitor.component.ts#TransferMonitorComponent`, which draws nothing, with no Live badge or sparkline because the Main artboard draws none; Dead-letter with Auto resubmit above zero; Scheduled; Transfer dead-letter; Size for a queue), with the words and order on [[pages/services/web-app/features-entities-main]].
- **Properties are text.** One two-column table per panel, built from rows the component computes (`web-app/src/app/features/entities/entity-details.component.ts#queueProperties`, `web-app/src/app/features/entities/entity-details.component.ts#topicProperties`, `web-app/src/app/features/entities/entity-details.component.ts#subscriptionProperties`). The subscription's read-only inputs, checkboxes, disabled browse buttons and its second table of counts are gone (rule 8); its counts are on the cards. A maximum delivery count or size the API did not send reads "Not set", where it used to be blank.
- **A failed load says so.** When reading the selected queue, topic or subscription fails, the panel says "Could not load the queue orders", the API's error and that nothing on the broker was changed, with Retry, which reads the selection again (`web-app/src/app/features/entities/entity-details.component.ts#Could not load the {{ state.selection.type }} {{ state.selection.node.name }}`). Before, a queue showed a blank panel and a subscription "Loading subscription details..." for ever.
- **The tree, the panel, its menus, delete and tabs** as the Main artboard draws them: [[pages/services/web-app/features-entities-main]].

**Entity definitions (2026-11-13),** under `features/entities/`. The tree header has Export definitions and Import definitions, two named icon buttons shown only when the API's own answer says `supportsDefinitions` is true; a default never turns them on (`web-app/src/app/features/entities/entities-tree.component.ts#EntitiesTreeComponent`, `web-app/src/app/core/services/provider.service.ts#map`). `DefinitionsService` posts to `namespace/export` and to `namespace/import` with `dryRun=true` or `false`, through `ApiService` (`web-app/src/app/core/services/definitions.service.ts#DefinitionsService`).
- **Export** (`export-definitions-dialog`) names the connection and its environment. Its facts are Queues, Topics, Subscriptions and Rules, then Messages (Not included) and Secrets (None); the four counts read "Counted when exported" until the export has read them, then come from the document the API returned (`web-app/src/app/features/entities/export-definitions-dialog.component.ts#countFacts`). Until the export is done it says "This is the slowest read in the app: every entity, and the rules of every subscription. It shows its progress and can be cancelled." It saves the API's document as `<namespace>.definitions.json` and says what it holds (`web-app/src/app/features/entities/export-definitions-dialog.component.ts#definitionsFileName`). Cancel stays enabled while it runs; it unsubscribes, which aborts the request, and the API stops reading because `NamespaceController#Export` passes `RequestAborted` down to `AzureEntityDefinitions#ExportCoreAsync`. A failure says nothing was saved and offers Retry.
- **Import** (`import-definitions-dialog`) reads a chosen file, refuses one that is not JSON before any call, and sends it to the dry run as read (`web-app/src/app/features/entities/import-definitions-dialog.component.ts#document`). The file line names the file, then "exported from <source>" when the file's `source` is a non-blank text, then its counts ("orders.definitions.json exported from contoso-dev: 4 queues, 1 topic, 2 subscriptions, 3 rules"); a file written before the export named its source, or one whose `source` is not a text, reads as before, the name and the counts (`web-app/src/app/features/entities/import-definitions-dialog.component.ts#read`). The dry run is one table, Entity / Kind / Result / Detail, in the order of the file, with the chips Already exists, Exists and differs and Would be created; the Detail reads "Same definition. Left as it is.", "With the configuration in the file." or "With its N rules.", and a difference gives each field in the words of the entity form with its value here and in the file, as the API's `differences` carry them ("Max delivery count is 5 here and 10 in the file. Left as it is."); an empty value reads "not set", and the rules read "The rules differ here." (`web-app/src/app/features/entities/import-definitions-dialog.component.ts#detail`). The notice splits "N already exist and M exists and differs" (`web-app/src/app/features/entities/import-definitions-dialog.component.ts#leftSentence`). The confirmation names the connection, the environment and the entities that would be created (`web-app/src/app/features/entities/import-definitions-dialog.component.ts#wouldBeCreated`); Create stays disabled until the namespace is typed exactly, case included, and sends the same document with `dryRun=false`. The result lists every entity: created, left as it is (exists, or differs, naming the fields in the words of the entity form, "Exists with another configuration (Max delivery count). Left as it is.", `web-app/src/app/features/entities/import-definitions-dialog.component.ts#outcomeText`) or failed with the API's reason; the tree is reloaded. A 400 or 413 is shown in the API's words, naming the field; an import the API does not confirm says some entities may exist now and offers the dry run again. With nothing to create there is no Create button. While the import runs the dialog cannot be closed, by Cancel, Escape or the backdrop, so its result is never abandoned half way.

### Entity selection and the purge confirmation

- `EntitySelectionService` clears the selection on every connection status after the one it starts with: a connect, a disconnect or the startup status (`web-app/src/app/core/services/entity-selection.service.ts#EntitySelectionService`). Only those three emit, so an entity selected under one connection is never shown, with its Purge, Send and View, under another; the tree no longer clears it on its own. A new selection or a clear cancels the load still in flight (`web-app/src/app/core/services/entity-selection.service.ts#select`, `web-app/src/app/core/services/entity-selection.service.ts#clearSelection`), so a late response neither overwrites a newer selection nor brings back one from the previous connection. Pinned by `web-app/src/app/core/services/entity-selection.service.spec.ts#after switching connection the previous connection\`.
- The purge confirmation names what it destroys, as on prototype artboard 3: the kind and name, the topic of a subscription, the connection target (namespace or host) and the count, the live one when the panel has it and otherwise the one read when the entity was loaded, said as such; it is confirmed by typing the queue or subscription name, the button disabled until the trimmed text equals it, case included (`web-app/src/app/features/entities/entity-details.component.ts#purgeMessages`, `web-app/src/app/shared/confirm-dialog.component.ts#confirmable`). The purges of the Queues and Topics screens, the delete-all of the messages dialog and the delete of an entity ask for the same typed name. Only a subscription has a live count today; a queue shows the count from selection.
