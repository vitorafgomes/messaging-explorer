# Web App: The Connections screen

One topic of [[pages/services/web-app|Web App]]; the API side is on [[pages/services/api/connections-and-secrets]].

`connections/` - connection list, add/edit dialog, client and environment groups, export of connections (`web-app/src/app/features/connections/connections.component.ts#ConnectionsComponent`). Since 2026-11-13 the screen and its three dialogs are Material and theme tokens, drawn from the Connections artboard: one table with a row group per client and environment, "Ungrouped Connections" last, columns Connection, Broker, Target and Actions; groups no longer collapse. Since 2026-11-14 the columns are Connection, Broker, Target, Environment and Last used: the environment as `EnvironmentChipComponent` (`web-app/src/app/shared/environment-chip.component.ts#EnvironmentChipComponent`), PRODUCTION, the environment's name or NO ENVIRONMENT, and the last use as a date or "Never". Edit shows Provider Type and Authentication as text and a stored secret as Stored with Replace, which opens "New <secret>" and "Keep the stored value"; a save without Replace sends the mask, never a value (`web-app/src/app/features/connections/add-connection-dialog.component.ts#secretValue`). RabbitMQ has the two TLS checkboxes. Manage Groups marks an environment Production (`web-app/src/app/features/connections/manage-group-dialog.component.ts#setProduction`). Import opens `ImportConnectionsDialogComponent` with the API's preview instead of a browser confirm. Under each name the way it signs in (`web-app/src/app/core/models/connection.model.ts#getConnectionAuthLabel`); the Connected chip takes the success container. A failed connect is an error above the table naming the connection and the reason the API classified, said with the target of the connection, or "Check the target, the credentials and the port of this connection." when it gave none (`web-app/src/app/features/connections/connections.component.ts#connectFailureSentence`), with Retry and Edit the connection; once the API answers the status after the failure, it says what is active: "The connection that was active stays active: <namespace>." only when that is still the one, else the connection now active or none. Deleting that connection removes the error. Delete opens the shared confirmation with the stored secret, the connection, broker, target and group ("Ungrouped, no environment" for an ungrouped connection), and for the active connection, the one the service connected or whose target the API reports, a notice that the app disconnects first, which it does before the delete (`web-app/src/app/features/connections/connections.component.ts#delete`). The groups dialog counts each client's environments and connections and each environment's connections, and asks before a delete in the same confirmation, naming the connections that stay saved without the group; a client with environments is refused first. A row offers Connect, or Open entities on the active connection, an edit icon button named "Edit {name}", and Delete apart in the error colour, named "Delete {name}". Loading, empty and a failed load are three states; a failed load says the connections could not be loaded and offers Retry, where it used to end on "No connections configured" (`web-app/src/app/features/connections/connections.component.ts#plural`). The empty state has its own Add Connection and Import, and the header actions are hidden there. Styles are in `connections.component.scss`. The developer-mode debug panel is left as it was, Bootstrap and Font Awesome included. Pinned by `web-app/src/app/features/connections/connections.component.spec.ts`; the masking of the dialogs is unchanged and still pinned by the two dialog specs.

**The add and edit dialog as the artboard draws it (2026-11-14).** Provider Type lists the two brokers without icons. Azure authentication is a radio group in a fieldset with the legend Authentication, in a column beside the fields. Since 2026-11-19 Add offers three options (`web-app/src/app/features/connections/add-connection-dialog.component.ts#azureAuthOptions`): Sign in with Microsoft (Recommended), Connection string and Azure CLI session (advanced); a stored Service Principal or Default credential connection still opens for edit under its own name (`web-app/src/app/features/connections/add-connection-dialog.component.ts#authLabel`); the selected one sits on the secondary container. The connection string is a single-line password input, "Masked as you type or paste."; the client secret has no hint, so the dialog no longer promises a secure store. Under Organization the dialog says what reaches `workspace.json` (`web-app/src/app/features/connections/add-connection-dialog.component.ts#storeNotice`): "Saved in plain text." on the warning container for a connection string, a client secret or a RabbitMQ password, and "No secret is saved." for sign-in, the Azure CLI and the default credential. RabbitMQ starts with Host Name, Username and Password empty; localhost is a placeholder and the password is never prefilled (`web-app/src/app/features/connections/add-connection-dialog.component.ts#onProviderTypeChange`). Edit shows Connection Name across the full width, then only the provider's non-secret fields. Pinned by `web-app/src/app/features/connections/add-connection-dialog.component.spec.ts#add, as the Connections artboard draws it`.

**Labels above 40 px fields (2026-11-15).** Add, Edit and Manage Groups put each label above its field and draw a 40 px field (`web-app/src/styles.scss#app-add-connection-dialog`); Organization follows the authentication and Transport comes after it; Manage Groups aligns its tabs to the start and reads each client or environment as one line, "Contoso 2 environments, 2 connections", and clears its form after an add (`web-app/src/app/features/connections/manage-group-dialog.component.ts#cancelEditClient`); its active tab is bold in the primary colour with a 3 px line, list headings are small and muted, form headings are on-surface, and edit and delete use the outline icons. Every dialog has a 20 px title on the surface container (`web-app/src/styles.scss#mat.dialog-overrides`). Add, Edit, Manage Groups and the imports open at their drawn width with `maxWidth: '95vw'`. Screenshots of every state: `web-app/e2e/ui-dialogs.e2e.ts#Connections dialogs as Connections.dc.html draws them`.

**Transport and proxy of an Azure connection (2026-11-14).** Add and edit show a Transport fieldset, AMQP (port 5671), the default, or AMQP over WebSockets (port 443), and Proxy address (optional), whose hint says the proxy is reached with the default credentials of this computer and no proxy user name or password is stored. `web-app/src/app/features/connections/add-connection-dialog.component.ts#proxyError` refuses, under the field and with Save disabled, an address that is not http or https, one with a user name or password, and a proxy on AMQP: the dialog never switches the transport by itself. Test and save of a connection string, and an edit, send `useWebSockets` and `proxyAddress`, an empty proxy left out; an edit loads both. Pinned by `web-app/src/app/features/connections/add-connection-dialog.component.spec.ts#AddConnectionDialogComponent - Azure transport and proxy`.

**Sign in, then pick (2026-11-19).** With Sign in with Microsoft or Azure CLI session, Add is three steps, drawn by the artboard's `si` block: "1 Sign in" (or "1 Azure CLI session"), "2 Client and environment", "3 Namespaces" (`web-app/src/app/features/connections/add-connection-dialog.component.ts#steps`). Step 1 takes an optional tenant and signs in through `web-app/src/app/core/services/azure-directory.service.ts#AzureDirectoryService`; the CLI path asks the CLI at once and shows "Session found" with Continue with this session and Check again. Step 2 picks the client and environment; step 3 lists the subscriptions ("N in this account") and the namespaces of the one picked, with loading, a failure as an error with Retry, and an empty sentence; a namespace already saved in that client and environment is ticked, disabled and "Already in {environment}". Ticks survive a change of subscription; a namespace can be typed by hand. Save, or "Add N connections", saves one connection per namespace through the existing save, named after it, with its tenant and resource ID (`web-app/src/app/features/connections/add-connection-dialog.component.ts#saveMany`); one that fails is named in an error and a second Save retries only it. On this path the Organization block, the transport and Test are not shown. Closing the dialog signs out. The API side is [[pages/services/core/azure-directory]]. Pinned by `web-app/src/app/features/connections/add-connection-dialog.component.spec.ts#AddConnectionDialogComponent - sign in, then pick, as the Connections artboard draws it`.

**The list is a tree (2026-11-19).** At the owner's word the connections are drawn as a block for each client, its environments inside as rows that hide and show their connections, and the connections with no client last (`web-app/src/app/features/connections/connections.component.ts#clientBlocks`). An environment left hidden is kept on this computer and opens hidden; one that holds the active connection says Connected on its row. Expand all and Collapse all act on every environment. The environment is the group, so a row carries no environment chip. Deleting a connection of an environment marked production asks for its name typed, and opening a connection for edit takes the failed-connect error off the screen.

**Deleting a client, a refused credential and the export (2026-11-19).** A client that has environments is deleted after a confirmation that names its environments and its connections; a production environment among them asks for the client's name typed (`web-app/src/app/features/connections/manage-group-dialog.component.ts#confirmGroupDelete`). A connect the broker refused for its user name or password says so (`credentials-refused`). In the desktop app an export is written where the user chooses in the system's save dialog (`web-app/src/app/features/connections/connections.component.ts#runFullExport`); in a browser it downloads as before.
