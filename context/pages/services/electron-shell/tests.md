# Electron Shell: Tests

One topic of [[pages/services/electron-shell|Electron Shell]]; the map lists the others.

## Tests

- `web-app/electron/shell-helpers.js` holds the testable decisions of main.js in plain CommonJS with no `electron` import: `isSafeExternalUrl`, `normalizeUpdateChannel`, `applyUpdateChannel`, `waitForHealth`, `stopProcess`, and since 2026-11-13 `applicationMenuTemplate`, `mainWindowOptions`, `shellShortcut` and `selfUpdateBlocker`, whose three reasons and the two packages that can update themselves are pinned by `web-app/electron/shell-helpers.test.js#a macOS build cannot update itself, because it is not signed`, `web-app/electron/shell-helpers.test.js#the portable Windows build cannot update itself; the installed one can` and `web-app/electron/shell-helpers.test.js#on Linux the AppImage and the deb can update themselves; any other package, or one of unknown type, cannot`. Since 2026-11-23 `readPackageType` is pinned on a deb, an absent, unreadable and empty file (`web-app/electron/shell-helpers.test.js#the package type is the trimmed text of resources/package-type`) and `packageKind` on what the page may be told (`web-app/electron/shell-helpers.test.js#the page is told the kind of package only as deb, appimage or nothing`). `configureAutoUpdate` is pinned on seven packages, a deb never installing on quit, by `web-app/electron/shell-helpers.test.js#a deb, which asks for the administrator password, never on quit`, and a picked version on a deb by `web-app/electron/shell-helpers.test.js#on a deb a picked version downloads`.
- `web-app/electron/shell-helpers.test.js` covers them with `node:test` and `node:assert/strict`, no dependency: no application menu on win32 and linux and exactly the three menus on darwin (`web-app/electron/shell-helpers.test.js#assert`, `web-app/electron/shell-helpers.test.js#no File/Edit/View/Window/Help bar: no application menu on win32 and linux`), the shell's shortcuts for each platform and build (`web-app/electron/shell-helpers.test.js#devToolsKeys` to `web-app/electron/shell-helpers.test.js#a packaged build never opens developer tools`), window options with no hidden title bar, traffic-light position or vibrancy and with the sandboxed web preferences (`web-app/electron/shell-helpers.test.js#windowPaths`), the background for each system theme (`web-app/electron/shell-helpers.test.js#options`), the accepted and refused URL schemes (`web-app/electron/shell-helpers.test.js#no blue flash: background follows the system theme`, `web-app/electron/shell-helpers.test.js#openExternal must not accept any URL scheme: http and https URLs are safe`), the two channels and the rejected values (`web-app/electron/shell-helpers.test.js#openExternal must not accept any URL scheme: file, javascript, custom schemes and garbage are refused`, `web-app/electron/shell-helpers.test.js#set-update-channel must reject a channel that is not latest or beta: latest and beta are kept`), what a channel applies to the updater, with a fake whose channel setter turns downgrades on as the library's does (`web-app/electron/shell-helpers.test.js#channel`, `web-app/electron/shell-helpers.test.js#updater`), the health outcomes healthy, exited and timeout, including a fetch that never settles (`web-app/electron/shell-helpers.test.js#updater`, `web-app/electron/shell-helpers.test.js#result`); since 2026-11-13 the two timeout cases run on the `node:test` fake clock (`setTimeout` and `Date`), so a five-minute deadline resolves in milliseconds and a stalled scheduler cannot change the count of attempts, and both `stopProcess` cases with a fake child whose `killed` turns true on the first signal (`web-app/electron/shell-helpers.test.js#timer`, `web-app/electron/shell-helpers.test.js#returned`).
- `web-app/electron/release-workflow.test.js` reads `.github/workflows/release.yml` as text and matches the upload globs of each OS against the files a stable and a beta build leave behind: the exact uploaded set, `beta*.yml` on a beta, the block maps, and never the builder's debug files (`web-app/electron/release-workflow.test.js#a stable release uploads latest*.yml and the packages for every OS`, `web-app/electron/release-workflow.test.js#a beta release uploads beta*.yml for every OS`, `web-app/electron/release-workflow.test.js#a release uploads the .blockmap files of the Windows installer and the macOS packages`, `web-app/electron/release-workflow.test.js#builder debug files are never uploaded`). Since 2026-11-23 it follows each `electron:build:<os>` script through the `npm run` it calls to its `dotnet publish` commands, and fails, naming the system and architecture, when one of win-x64, linux-x64, osx-arm64 and osx-x64 is not published, not `--self-contained`, trimmed or single-file, or written to another folder than `extraResources.from` expands to for that `${os}` and `${arch}` (`web-app/electron/release-workflow.test.js#every installer carries the API published self-contained for its own system and architecture, so the user needs no .NET`). `describeApiExit` is pinned on both runtime codes, another code, a launch error and a signal (`web-app/electron/shell-helpers.test.js#an API that cannot find the .NET runtime is told as that, with what to do; any other end keeps its own sentence`).
- Run with `npm run test:electron` in `web-app/` (`web-app/package.json`); CI runs it in the `web` job after the Angular tests (`.github/workflows/ci.yml#working-directory: web-app`).
- `web-app/electron/preload.test.js` loads the preload with a fake `electron` module (no Electron) and pins what it exposes; see the IPC surface. Since 2026-11-13 the fake records the channel of each `invoke`, and `getSelfUpdateBlocker` is pinned to `get-self-update-blocker` (`web-app/electron/preload.test.js#getSelfUpdateBlocker reads the get-self-update-blocker channel and sends nothing with it`), and since 2026-11-23 `getPackageType` to `get-package-type` with no argument (`web-app/electron/preload.test.js#getPackageType reads the get-package-type channel and sends no argument`).
- Since 2026-11-20 the question before a quit is decided by `quitDecision` and the count it reads by `acceptActiveRuns` (`web-app/electron/shell-helpers.js`): no run quits without asking, Keep running cancels, Quit and stop quits, several runs read in the plural, the quit of an update and a quit already agreed to never ask, and a count that is not a whole number from 0 to 1000, or from another sender, keeps the last one (`web-app/electron/shell-helpers.test.js#the quit that installs an update is never asked about, so quitAndInstall is not blocked`, `web-app/electron/shell-helpers.test.js#the count of active runs is taken only as a whole number from 0 to 1000 from the main window, else the last valid one stays`). A text match pins that `before-quit` decides before it stops the API and that the update's event is read on Electron's own `autoUpdater`. `web-app/electron/preload.test.js#the preload exposes exactly these members, setActiveRuns included` pins the whole bridge.
- No test starts Electron. The wiring in main.js (the dialogs, the native box itself, the window opening after the wait, the IPC handlers) is untested.
