# Api

> The local HTTP door of Messaging Explorer: one authenticated loopback REST surface that holds a single active broker connection and forwards every call to the Core provider.

## Responsibility

Owns the HTTP surface: startup configuration, the auth/CORS/host-filter pipeline, route shape, request clamping, error-to-status mapping, and the one slot that holds the active provider. Does not own broker behaviour, bulk-operation semantics or connection persistence; those live in [[pages/services/core]]. Does not serve the UI ([[pages/services/web-app]]) and does not start itself ([[pages/services/electron-shell]]). See [[pages/architecture/project-map]].

## Public contract

- **HTTP routes:** `api/{controller}` for `connections`, `connectiongroups`, `queues`, `topics`, `metrics`, `monitoring`, and `api/namespace` for the entity definitions (`src/ServiceBusExplorer.Api/Controllers/NamespaceController.cs:30`, `src/ServiceBusExplorer.Api/Controllers/NamespaceController.cs:54`) (`[Route("api/[controller]")]`, for example `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:8`); the session routes sit under `api/queues/{name}/sessions` and `api/topics/{topic}/subscriptions/{subscription}/sessions` with absolute templates (`src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:17`), plus unauthenticated `GET /health` (`src/ServiceBusExplorer.Api/Program.cs:186`) and, in Development only, the OpenAPI document (`src/ServiceBusExplorer.Api/Program.cs:168`).
- **HTTP routes:** `api/{controller}` for `connections`, `connectiongroups`, `queues`, `topics`, `metrics`, `monitoring` (`snapshot`, `history`, `counts`) (`[Route("api/[controller]")]`, for example `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:8`); the session routes sit under `api/queues/{name}/sessions` and `api/topics/{topic}/subscriptions/{subscription}/sessions` with absolute templates (`src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:17`), plus unauthenticated `GET /health` (`src/ServiceBusExplorer.Api/Program.cs:186`) and, in Development only, the OpenAPI document (`src/ServiceBusExplorer.Api/Program.cs:168`).
- **Auth:** every request except `OPTIONS` and `/health*` needs header `X-Api-Key` equal to `API_SECRET` ([[pages/invariants/local-authenticated-api]]).
- **JSON:** camelCase, enums as strings in both directions (`src/ServiceBusExplorer.Api/Program.cs:55`, `:59`). The import/export files on disk stay PascalCase (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs:496`).
- **Events:** none published or consumed. **Direct callers:** the Angular app in Electron (`X-Api-Key` set at `web-app/electron/main.js:236`).

## Startup and composition

Everything is in `src/ServiceBusExplorer.Api/Program.cs`, top-level statements, in this order:

- **Ports** (`:228`): `EXPLORER_CONFIG_PATH` if the file exists and parses (`:231`), else walk up from `AppContext.BaseDirectory` for the first parsable `config.json` (`:239-246`), else defaults 5917 (API) and 4297 (frontend) with a warning (`:25-26`, `:249`). Only `apiPort` and `frontendPort` are read (`:263-266`); a parse failure logs the path and exception type, not the message (`:272`).
- **Secret** (`:36-42`): `API_SECRET` must be at least 32 characters or the process logs Critical and calls `Environment.Exit(1)` before the host is built. Bytes cached once (`:45`). Pinned by `src/ServiceBusExplorer.Api.Tests/BoundaryGuardTests.cs:29`, which starts the built API as a child process with the variable unset and with 31 characters and expects exit code 1 in both cases.
- **JSON** (`:50-60`), **OpenAPI** services (`:61-62`).
- **CORS** policy `AllowAngular` (`:66-77`): origins `http://localhost:{frontendPort}`, `http://127.0.0.1:{frontendPort}` and the literal `null` (the origin a `file://` Electron page sends), any header, any method.
- **Host filtering** (`:80-83`): `AllowedHosts = ["localhost", "127.0.0.1"]` set in code.
- **Kestrel** (`:86-89`): `ListenLocalhost(apiPort)` only when `ASPNETCORE_URLS` is empty. When it is set the code binds nothing itself and the URLs win. Electron always sets it to `http://localhost:{apiPort}` (`web-app/electron/main.js:634`, `:848`), so under Electron the in-code loopback binding is not the one in effect; the bind address is whatever the shell passes.
- **Data path** (`:92-101`): `SERVICEBUS_DATA_PATH`, else `%APPDATA%/ServiceBusExplorer` equivalent; created if missing.
- **DI** (all singletons): `IConnectionManager` = `FileWorkspaceManager` (`:103`), `IConnectionGroupManager` = the same instance cast (`:107`), `IProviderFactory` (`:110`), `IServiceBusService` (`:117`, a legacy Azure-only service, see Known gaps), `MonitoringStore` (`:123`), hosted `MonitoringBackgroundService` (`:124`), `IMemoryCache` (`:139`).
- **Metrics** (`:133-164`): `AzureMonitorOptions.IsConfigured` needs `SubscriptionId`, `ResourceGroup` and `Namespace` all non-blank (`src/ServiceBusExplorer.Core/Services/AzureMonitorOptions.cs:29`). If true, `AzureMonitorMetricsService` with `credential: null` (`:146-157`); otherwise `UnconfiguredMetricsService` (`:163`), which throws an `InvalidOperationException` whose text contains "not properly configured" (`src/ServiceBusExplorer.Core/Services/UnconfiguredMetricsService.cs:14`) and the controller turns into 503.
- **Pipeline** (`:175-221`): the exception handler (`:175`), host filtering, CORS, `MapGet("/health")`, the key middleware, authorization, `MapControllers`. No HTTPS redirection (`:218-219`).

```mermaid
flowchart LR
    R[Request] --> E[ExceptionHandler]
    E --> H[HostFiltering]
    H --> C[CORS AllowAngular]
    C --> K{X-Api-Key middleware}
    K -- "OPTIONS or /health" --> N[next]
    K -- "FixedTimeEquals fails" --> U[401 Unauthorized]
    K -- ok --> N
    N --> CT[Controller action]
    CT --> G["ConnectionsController.GetCurrentProvider (static)"]
    G --> P[IMessagingProvider in Core]
```

The key middleware (`:189-216`) skips `OPTIONS` (`:192`) and any path under `/health` (`:198`), then compares UTF-8 bytes of the header against the cached secret: length check first, then `CryptographicOperations.FixedTimeEquals` (`:207-208`). The length check is not constant time, which only reveals the secret's length. A missing header is treated as empty bytes (`:205`). Failure answers 401 `{message:"Unauthorized"}`; a 401 is a response, not an exception, so the exception handler does not touch it.

**Host filtering vs `"AllowedHosts": "*"`:** `src/ServiceBusExplorer.Api/appsettings.json:8` sets `"*"` while the code sets an explicit list (`src/ServiceBusExplorer.Api/Program.cs:82`). The list in code is the one in effect: a request with `Host: evil.example` and a valid key answers 400, one with `Host: 127.0.0.1` answers 200 (`src/ServiceBusExplorer.Api.Tests/BoundaryGuardTests.cs:15`), and widening the list in code to `"*"` makes the foreign host answer 200. The `"*"` in `appsettings.json` has no effect on this filter.

## Controllers

**Entity administration (2026-11-12).** `POST` on queues, topics and subscriptions takes `{ name, options }` with typed fields and no dictionary (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:57`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:57`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:162`); `PATCH` on each edits only the fields sent and returns the entity read again (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:84`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:84`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:189`). The controllers know no limit: the provider validates. They map the provider's neutral exceptions to 409 already exists, 404 not found and 400 invalid configuration, a provider that cannot update to 400, anything else to the constant 500 body (`src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:44`). A response never carries the broker's text and a log line never carries the request body.

**Sub-queues, scheduled messages and a disabled entity (2026-11-12).** The active, dead-letter and transfer dead-letter routes of an operation are one-line actions over one private action that takes a `MessageSubQueue` (for example `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:130`, `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:163`). Eight routes read the transfer dead-letter queue, four for a queue and four for a subscription, mirroring the dead-letter peek, search, delete-batch and resubmit-batch (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:159`, `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:126`, `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:360`, `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:297`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:356`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:322`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:494`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:429`); a provider without `SupportsTransferDeadLetter` answers 400 and is never called (`src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:29`), there is no purge and no move for it, and its delete-batch refuses `all: true` with 400 (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:370`, `src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:21`). `POST api/queues/{name}/messages/cancel-scheduled` takes `{ sequenceNumbers }` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:241`), answers the result in the delete-batch shape, 400 with the provider's own text when it refuses the numbers (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:255`) and 400 for a provider without scheduled messages (`src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:23`); queues only. **Peek from a position (2026-11-13).** The four dead-letter and transfer dead-letter peek routes, of a queue and of a subscription, take an optional `fromSequenceNumber` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:159`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:356`); the active peek does not. It is bound as text and read as a whole number of 0 or more, digits only (`src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:66`): a sign, a space, a decimal, an exponent or a value past `long` answers 400 `{ "message": "fromSequenceNumber must be a whole number of 0 or more." }`, never the framework's validation body, and the provider is not called. An empty value (`?fromSequenceNumber=`) counts as absent. A provider without `SupportsPeekFromSequenceNumber` answers 400 `{ "message": "This provider cannot read the dead-letter queue from a position." }` when the parameter is present and is never called (`src/ServiceBusExplorer.Api/Controllers/EntityAdministrationResults.cs:72`); the check runs before the transfer dead-letter check, so RabbitMQ gives that text on all four routes (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:169`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:366`). Otherwise the value reaches the provider's peek with the clamped count and the request token, and the answer is the messages from that sequence number on, in order ([[pages/services/core]]). Absent, a route answers as before. A failing peek from a position answers what a failing peek from the head answers, the constant 500. The capabilities answer carries `supportsPeekFromSequenceNumber` (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs:398`). Pinned by `src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs`: the pass-through on the four routes and position 0 (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:265`, `src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:278`), the absent and empty value (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:294`), the refused values (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:315`), the provider without the capability with and without the parameter (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:327`, `src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:340`), the failing call (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:350`), the capability (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:365`) and the API key (`src/ServiceBusExplorer.Api.Tests/MessageRouteTests.cs:381`).

**Peek without bodies (2026-11-13).** The same four routes take an optional `includeBody`, true when absent or empty. `false` answers each message with `"body": null` and every other field as read, size included; the run of the automatic resubmit reads only the sequence number, the enqueued time, the reason and the subject, so it no longer copies every body of the queue over loopback. **Sessions (2026-11-13).** Eight routes replace the four under `api/sessions`. Each base, a queue and a subscription, has a list (`GET .../sessions?maxMessages=`, default 1000, clamped to 1..5000, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:65`), the detail of one session (`GET .../sessions/{sessionId}?messageCount=`, absent or 0 for no messages, clamped to 0..1000, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:39`; one accept reads the state and peeks up to that many messages, answered as `messages` in the peek route's shape, `null` when not asked), its messages (`GET .../sessions/{sessionId}/messages?count=`, the peek route's default 10 and limit 1..1000, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:47`) and a state write (`PUT .../sessions/{sessionId}/state`). The list answers `{ sessions: [{ sessionId, messageCount, firstSequenceNumber }], scannedMessages, truncated }` and locks nothing; the detail answers `{ sessionId, state, stateIsBinary, lockedUntil, messages }`; the other three accept one session and release it before the answer ([[pages/services/core]]). The write takes `{ state, expectedState }`, both required and bound as a `JsonElement`. An absent property, a missing body or a value that is not a string answers 400 with a fixed text, and the provider is never called (`src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:69`, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:74`). A `state` of `null` or `""` clears the state. An `expectedState` of `null` or `""` means the session had no state. One runner hands the provider the request token and maps every failure (`src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:91`, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:106`, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:114`):
- 400 for a provider without `SupportsSessions`, which is never called;
- 400 for an entity without sessions, a binary state and an id or state the provider refused, each with its fixed text;
- 404 `The queue was not found.` or `The subscription was not found.`;
- 409 `{ message, code: "SessionInUse" }` for a session another receiver holds or a five-second accept that elapsed;
- 409 `{ message, code: "SessionStateChanged" }` when the state changed since it was read;
- 409 `The entity is disabled for this operation.` for a disabled entity, as on every other message route;
- anything else the constant 500, the exception logged at Error with the operation, the entity path and the session id, never the state (`src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:124`).

Pinned by `src/ServiceBusExplorer.Api.Tests/SessionRouteTests.cs`, the detail's `messageCount` clamp and `messages` body included (`src/ServiceBusExplorer.Api.Tests/SessionRouteTests.cs:109`, `src/ServiceBusExplorer.Api.Tests/SessionRouteTests.cs:118`). Known limits: an empty entity that does not use sessions lists as empty instead of answering 400, because a peek cannot tell it from an empty session entity. At the cap of 100 sessions, `truncated` is true and `scannedMessages` counts only the messages before the 101st session. Seen on the emulator only, not on a real namespace: accepting a session of an entity without sessions throws `InvalidOperationException`, an unknown session id is accepted with no state, and a session receiver's peek can return a short batch.

### How the active provider is obtained

`QueuesController`, `TopicsController` and `SessionsController` take only a logger. Each declares a private static `GetProvider()` that returns `ConnectionsController.GetCurrentProvider()` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:22`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:22`, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:27`). That is a public static read of `ConnectionsController._currentProvider`, a static field guarded by a lock for reads and swaps (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs:24-25`, `:50-53`, `:411`). `MonitoringBackgroundService` reads the same slot (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:89`).
`QueuesController`, `TopicsController` and `SessionsController` take only a logger. Each declares a private static `GetProvider()` that returns `ConnectionsController.GetCurrentProvider()` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:22`, `src/ServiceBusExplorer.Api/Controllers/TopicsController.cs:22`, `src/ServiceBusExplorer.Api/Controllers/SessionsController.cs:27`). That is a public static read of `ConnectionsController._currentProvider`, a static field guarded by a lock for reads and swaps (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs:24-25`, `:50-53`, `:410`). `MonitoringBackgroundService` and the `counts` route of `MonitoringController` read the same slot (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:87`, `src/ServiceBusExplorer.Api/Controllers/MonitoringController.cs:54`).

Consequences:

- One active connection per process, shared by every client of the API. Connecting replaces it for everyone ([[pages/invariants/provider-boundaries]]).
- With no connection, every provider-backed action returns 400 `{message:"No messaging provider connected..."}` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:27-30`), the same text duplicated in each of the three controllers.
- The lock covers only the field. `SetCurrentProviderAsync` swaps under the lock, then disconnects and disposes the old provider outside it (`.../ConnectionsController.cs:59-80`). An action that already read the old reference at its start (for example `src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:35`) keeps using it with no lease, so a concurrent `connect`, `disconnect` or `clear-all` can dispose the provider under a running call. No test covers it.
- `Connect` creates and connects the new provider before the swap (`.../ConnectionsController.cs:240-243`); if creation throws, the previous provider stays active and the caller gets 500.
- `GetStatus` falls back to the legacy `IServiceBusService` when no provider is set (`.../ConnectionsController.cs:326-332`).

### Entity names in the path

An entity, topic, subscription or session name is one path segment, sent percent-encoded by the web app ([[pages/services/web-app]]). Kestrel decodes every escape in the path except `%2F`, so by default the route value of `/api/queues/a%2Fmessages` is the literal `a%2Fmessages`, while `%25`, `%23`, `%3F` and `%20` are decoded: a raw `a%252Fb` and a raw `a%2Fb` both reach the action as `a%2Fb`. Decoding the route value again would turn the first into `a/b`, so the route value alone cannot be fixed.

`RawTargetRouteValuesAttribute` (`src/ServiceBusExplorer.Api/Controllers/RawTargetRouteValuesAttribute.cs:16`), a resource filter on `QueuesController`, `TopicsController`, `SessionsController` and `MetricsController` (`src/ServiceBusExplorer.Api/Controllers/QueuesController.cs:7`), runs before model binding and replaces each whole-segment route value with the matching segment of the raw request target, decoded once (`src/ServiceBusExplorer.Api/Controllers/RawTargetRouteValuesAttribute.cs:59`): `a%2Fmessages` reaches the provider as `a/messages`, `a%252Fb` as `a%2Fb`, `50%25off` as `50%off`. It replaces a value only when the raw target is an origin-form path with as many segments as the route pattern (`:47`) and the raw segment decodes, `%2F` kept, to the value routing produced (`:57`); otherwise, for example a raw target with dot segments that Kestrel normalised, the routed value is left as it was. Routes are unchanged. `ConnectionsController` and `ConnectionGroupsController` carry ids, not names, and do not use it.

Pinned through Kestrel (`WebApplicationFactory.UseKestrel`) by `src/ServiceBusExplorer.Api.Tests/EntityNameRoutingTests.cs`: deleting the queue `a/messages` calls `DeleteQueueAsync("a/messages")` and nothing else (`:98`); purging `orders#1` calls `PurgeMessagesAsync("orders#1")` and nothing else (`:106`); eight queue names on six queue operations (`:122`), a topic and subscription with `/` (`:144`), a session id with `/` and a space on the six session-id routes and the two lists (`:248`) and the three metrics routes (`:176`) reach the provider or the metrics service unchanged; the fallback branches are driven directly (`:197`, `:210`).

## Monitoring

**The poll.** `MonitoringBackgroundService` starts a poll at startup and then on every tick of a `PeriodicTimer` (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:72`). The period is `Monitoring:PollIntervalSeconds` in whole seconds, raised to a floor of 30 seconds and lowered to a ceiling of one hour; an absent or unparsable value is the floor (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:59`). No `appsettings` file sets the key, so the period is 30 seconds unless the environment says otherwise (`Monitoring__PollIntervalSeconds`). The floor is the proposal of the monitoring artboard: the tool must not hammer a production namespace. The timer takes a `TimeProvider`, the system clock outside tests. The poll runs whenever a broker is connected, whether or not the screen is open ([[pages/roadmap/followups]]). A tick that finds the previous poll still running is skipped and logged at Warning (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:88`), so a slow namespace never has two polls in flight. A tick after the connection changed does not wait for a poll of the previous connection: it cancels that poll, whose subscription reads stop between topics and whose answer is discarded, and polls the current connection at once (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:90`).

A poll reads the current provider, clears the store when the provider reference changed (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:117`), returns if none or disconnected (`:121`), then calls `GetQueuesAsync` and `GetTopicsAsync` once each and `GetSubscriptionsAsync` per topic, at most four topics at a time (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:26`, `src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:153`): on Azure each is one management request, so four keeps a namespace of many topics from costing one round trip after another while never holding more than four requests open against it. On RabbitMQ each topic costs one request for its bindings and then two per queue it binds (the queue and its `.dlq`), one after another: still at most four requests open, but many more round trips per poll; a binding to another exchange is skipped (`src/ServiceBusExplorer.Core/Providers/RabbitMQ/RabbitMQProvider.cs:358`, [[pages/roadmap/followups]]). The subscriptions are kept in topic order. One failing call fails the whole poll: no partial snapshot is stored, the exception is logged at Error and the store records the time of the failure (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:141`); the next tick polls again, and its snapshot clears the failure. A poll that ends after the connection changed stores nothing (`src/ServiceBusExplorer.Api/Monitoring/MonitoringBackgroundService.cs:127`).

**The counts.** Each queue and subscription carries active, dead-letter, transfer, scheduled and transfer dead-letter counts. A count the broker does not count is `null`, never 0 (`src/ServiceBusExplorer.Api/Monitoring/MonitoringModels.cs:37`): the scheduled count of a subscription always, because `SubscriptionRuntimeProperties` in `Azure.Messaging.ServiceBus` 7.21 has no scheduled count (read in the installed package: total, active, dead-letter, transfer and transfer dead-letter only); the scheduled count of a provider without `SupportsScheduledMessages` and the transfer dead-letter count of a provider without `SupportsTransferDeadLetter`, both RabbitMQ. The web app says "Not counted".

**The routes.** `MonitoringStore` is a `ConcurrentQueue` capped at 120 snapshots (`src/ServiceBusExplorer.Api/Monitoring/MonitoringStore.cs:7`) plus the time of the last failed poll. `GET api/monitoring/snapshot` answers `{ snapshot, pollIntervalSeconds, lastPollFailedAt }` (`src/ServiceBusExplorer.Api/Controllers/MonitoringController.cs:21`): `snapshot` is `null` until a poll has stored one, where it used to be an empty snapshot stamped now that read like an empty namespace, and `lastPollFailedAt` is the time of the last failed poll, `null` once a later poll succeeded; nothing of the exception reaches the answer. `GET api/monitoring/counts?queue={name}` or `?topic={topic}&subscription={subscription}` reads one entity's counts from the broker now, outside the poll, in the snapshot's shape, and writes nothing to the store (`src/ServiceBusExplorer.Api/Controllers/MonitoringController.cs:46`). One route takes both kinds as query values, so a name with `/` needs no raw-target decoding. It answers 400 `Name either a queue, or a topic and one of its subscriptions.` when it names neither or both, without calling the provider (`:51`); 400 with no provider connected; 404 `The queue was not found.` or `The subscription was not found.`; the constant 500 for any other failure, logged with the entity path (`:73`). It hands the provider the request token through `GetQueueCountsAsync` and `GetSubscriptionCountsAsync`, one runtime-properties call each on Azure ([[pages/services/core]]).
