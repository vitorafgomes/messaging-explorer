# Api: Connections and secrets

One topic of [[pages/services/api|Api]]; the map lists the others.

## Connections and secrets

Paths written `.../` abbreviate `src/ServiceBusExplorer.Api/Controllers/`.

- **Test (2026-11-15):** with an `id`, a secret sent as `***` becomes the stored one, as on save (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#RestoreMaskedSecrets`).
- **Masking:** list and get return masked copies (`***` for `ConnectionString`, `Password`, `ClientSecret`) from `FileWorkspaceManager` (`src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#MaskConnection`, `:321`); raw secrets come only from `GetConnectionWithSecretAsync` (`:325`), which `Connect` and `SaveConnection` call (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#SaveConnection`, `:233`) ([[pages/invariants/secrets-masked-at-the-api-boundary]]). Since 2026-11-15 list and get name an Azure connection's endpoint host as `namespace`, never its key (`src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#MaskedWithTarget`); export and the save answer do not.
- **Save with placeholder:** if the body carries an `Id` that exists, `***` in `ConnectionString` or `Password` is replaced by the stored value (`.../ConnectionsController.cs:125-133`) before the equality check that decides a "metadata only" update. A metadata-only update skips the connection test (`:146`, `:155`). The manager keeps the stored value for any of the three secrets that still arrives as `***` (`src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#CopyEditableFields`, `:348`, `:357`) and returns the masked clone of what it stored, which the action returns as the POST body (`src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#SaveConnectionAsync`, `src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#SaveConnection`).
- **Unreadable `workspace.json`:** every manager read throws `InvalidOperationException` ([[pages/services/core]]). Actions with a `try/catch` answer 500 `{message:"An internal error occurred."}`: list, save, connect, import (the exception is neither `ArgumentException` nor `JsonException`, so it is not a 400), `export-full` and `import-full` (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#GetConnections`, `:178`, `:260`, `:464`, `:505`, `:564`). `clear-all` is the in-app recovery: it answers 200 with zero counts and leaves an empty workspace (pinned by `src/ServiceBusExplorer.Api.Tests/ClearAllTests.cs#Clear_all_recovers_an_unreadable_workspace`). GET by id, `DELETE {id}` and `export` have no `try/catch` (`:100`, `:412`, `:419`); the exception handler answers them with the constant 500 in every environment (`src/ServiceBusExplorer.Api.Tests/ErrorBodyTests.cs#An_unhandled_exception_answers_a_constant_500_body_and_never_the_exception_text`).
- **A failed connect** answers why only as a fixed `code` and sentence (`connection-refused`, `host-not-found`, `timeout`, `tls`), read from BCL exception types in the chain, never from the exception text (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ConnectFailureReason`, pinned by `src/ServiceBusExplorer.Api.Tests/ConnectFailureReasonTests.cs`). A refused user name or password is not among them: the RabbitMQ refusal is a `RabbitMQ.Client` type the API may not name, so it keeps the general body.
- **`export`:** `POST`, masked by default; `?includeSecrets=true` returns raw and sets `Content-Disposition: attachment` and logs the remote IP (`.../ConnectionsController.cs:420-431`). **`export-full`:** same flag, adds groups, indented PascalCase JSON (`:471-503`). **`import`:** string payload to the manager (`:433-469`). **`import-full`:** checks every connection's proxy first and answers 400 importing nothing; then groups saved first, then connections, with no rollback if the second step fails (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ImportFullConfiguration`).
- **`clear-all`** (`DELETE`, no confirmation parameter): disconnects the provider and the legacy service (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ClearAllData`), then calls `IConnectionManager.ClearAllAsync` (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ClearAllData`), which counts what is stored and writes an empty workspace under the manager's lock through the temp-file-and-move save ([[pages/services/core]]). The body is `{message, connectionsDeleted, groupsDeleted}`; an unreadable file reports zero for both and is still reset. A failed write answers the constant 500.
- **`ConnectionMaskingTests.cs` pins** (`src/ServiceBusExplorer.Api.Tests/ConnectionMaskingTests.cs#GetConnection_by_id_returns_masked_connection_string`): GET by id masks `connectionString` and `clientSecret` (`:81`); default export masks both and does not leak the sentinel (`:41`, `:103`); `includeSecrets=true` returns raw values and a content-disposition (`:61`, `:127`); GET by id and the default export mask `password` (`:150`, `:170`); a metadata-only `POST` answers with `***` for all three secrets (`:196`). It does not pin the list endpoint, `export-full`, any import through the API or `clear-all`; the import merge is pinned in Core (`src/ServiceBusExplorer.Core.Tests/Services/FileWorkspaceManagerTests.cs#Importing_an_existing_id_persists_its_RabbitMQ_fields`, `:155`).

**Since 2026-11-14** (proof for [[pages/invariants/secrets-masked-at-the-api-boundary]]).
- **Import preview.** `POST connections/import/preview` (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#PreviewImport`) takes the import-full body, parses it with the same `ParseFullConfiguration` as the import, compares ids with what is stored and writes nothing. It answers the items to add and update, built only from name, kind, target and placement, never from a secret field, with `keepsStoredSecret` where a stored connection arrives masked, `secretsMasked` and the stored connections the file does not hold. Invalid JSON answers 400 "Invalid JSON format.", an empty body 400, an unreadable workspace the constant 500. It sits behind the key middleware like every route. Pinned by `src/ServiceBusExplorer.Api.Tests/ImportPreviewTests.cs#The_preview_never_carries_a_secret_of_the_file_or_of_the_workspace` and `src/ServiceBusExplorer.Api.Tests/ImportPreviewTests.cs#The_preview_without_the_key_is_401`.
- **An edit keeps every secret it did not replace.** The save restores a masked `ClientSecret` as it does the connection string and the password, and its metadata-only check also compares `UseSsl`, `UseManagementSsl` and `ClientSecret`, so an edit of a TLS flag alone is tested before it is saved (`src/ServiceBusExplorer.Api.Tests/ConnectionMaskingTests.cs#An_edit_that_changes_only_a_TLS_flag_is_tested_before_it_is_saved`); pinned per secret by `src/ServiceBusExplorer.Api.Tests/ConnectionMaskingTests.cs#An_edit_save_keeps_a_stored_secret_it_did_not_replace_and_stores_one_it_replaced`.
- **Connect records its last use** through `IConnectionManager.MarkUsedAsync`; a write that fails is logged and the connect still answers connected (`src/ServiceBusExplorer.Api.Tests/ConnectionLastUsedTests.cs#A_connect_whose_last_use_cannot_be_written_still_answers_connected`).

- **Transport and proxy (2026-11-14).** `UseWebSockets` and `ProxyAddress` are stored, returned by the masked reads, exported and imported like the other non-secret fields. They are not a secret, because a proxy that could carry one is refused on every write, by one rule (`src/ServiceBusExplorer.Core/Models/ServiceBusConnection.cs#HasAllowedProxy`): on Azure Service Bus an absolute http or https address with no user name or password, on a WebSockets connection; on RabbitMQ, which has no proxy in this app, none at all. The save checks it before the connection test, so nothing is tried, and answers 400 with the fixed `src/ServiceBusExplorer.Core/Models/ServiceBusConnection.cs#ProxyRefusal`, never the address (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#SaveConnection`); the shared write path refuses it too (`src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#SaveConnectionAsync`, `src/ServiceBusExplorer.Core/Services/FileWorkspaceManager.cs#ImportConfigurationAsync`). An import holding one answers 400 "Invalid or empty configuration data"; `import-full` checks every connection of the file before the first group is saved and answers 400 with the fixed text, importing nothing (`src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ImportFullConfiguration`). Until 2026-11-14 a RabbitMQ save stored a proxy with a password and the masked reads returned it, and `import-full` saved the groups before the import refused the proxy. Pinned by `src/ServiceBusExplorer.Api.Tests/ConnectionFailureLogTests.cs#A_save_whose_proxy_address_carries_a_user_name_and_password_is_refused_never_stored_and_never_logged`, `#A_save_of_a_RabbitMQ_connection_with_a_proxy_is_refused_with_the_fixed_text_never_stored_and_never_logged`, `#An_import_full_with_one_disallowed_proxy_is_refused_with_the_fixed_text_and_imports_no_group_and_no_connection` (the proxy password absent from the body, every log entry and the console), and `src/ServiceBusExplorer.Core.Tests/Services/FileWorkspaceManagerTests.cs#A_save_with_a_proxy_the_provider_cannot_use_is_refused_with_the_fixed_text_and_stores_nothing`. A connection stored with such a proxy before the change is not cleaned. The metadata-only check compares both, so an edit of the transport or the proxy alone is tested before it is saved (`src/ServiceBusExplorer.Api.Tests/ConnectionMaskingTests.cs#An_edit_that_changes_only_the_transport_or_the_proxy_is_tested_before_it_is_saved`). A test or save through a proxy that refuses fails like any other: `success:false`, 400, nothing stored, no key in the log (`src/ServiceBusExplorer.Api.Tests/ConnectionFailureLogTests.cs#A_test_and_a_save_over_WebSockets_through_a_proxy_that_refuses_fail_like_any_other_and_never_log_the_key`). Azure clients connect lazily, so `connect` answers connected and `src/ServiceBusExplorer.Api/Controllers/ConnectionsController.cs#ConnectFailureReason` is not reached by a transport failure; it is unchanged.

**Azure resource ID (2026-11-14).** `ServiceBusConnection.AzureResourceId` is not a secret: masked reads and the default export carry it, the merge copies it, and `SaveConnection` and `import-full` refuse a value out of the namespace format, or any value on RabbitMQ, with the fixed `ResourceIdRefusal` and store nothing (`src/ServiceBusExplorer.Core/Models/ServiceBusConnection.cs#HasAllowedResourceId`). It is not part of the metadata-only comparison, so an edit of it alone is saved without a connection test: it is not how the broker is reached. Pinned by `src/ServiceBusExplorer.Api.Tests/NamespaceMetricsRouteTests.cs#A_resource_id_edit_alone_is_metadata_it_is_stored_untested_and_read_back_unmasked`.
