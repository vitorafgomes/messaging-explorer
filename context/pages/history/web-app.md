# Web App history

What changed when in the project [[pages/services/web-app|Web App]] describes, newest first.

## Version notes until 2026-11-13

The `changes` field of the service page header as it stood when the page became a map, cut at each "Earlier", in its words.

- 2026-11-13: the shared selection bar, Advanced Filters, bulk progress and results dialogs, the Monitoring Overview and the Queues and Topics pages are Material and theme tokens; the selection bar stays on screen with nothing selected and sets Delete apart in the error colour; the Overview draws its trend as two sparklines; a failed load of the Queues or Topics page is an error with Retry and their purges are in a menu.
- Earlier 2026-11-13: the Connections screen and its dialogs are Material and theme tokens, one table grouped by client and environment, a failed load is an error with Retry.
- Earlier 2026-11-13: 2026-11-13: a Settings screen, reached from a toolbar icon: updates with every state, the channel and a package that cannot update itself, the data file and Clear all data behind a typed confirmation, developer mode, About; the version badge and its channel menu left the toolbar, which keeps a compact update link; Clear All Data left the connections debug panel; the update state lives in AppUpdateService and the error capture of the bug report in BugReportService.
- Earlier 2026-11-13: an auto resubmit run waits the lock duration and tries a message not found once more before it ends, never moving past it; continuing covers refused messages and possible duplicates only; a filter warns that the run may stop early.
- Earlier 2026-11-13: an auto resubmit run is stopped and ended before a connect, disconnect or clear of all data is posted, none starts until the status after it arrives, and a failed connect reads the status again; it ends at a batch that comes back all not found; 250 per batch; no bodies peeked without a text filter.
- Earlier 2026-11-13: the automatic dead-letter resubmit is a run kept by the app, reading onward from a sequence number, bounded by the count at its start, continuing past a failure, with pause, stop, a toolbar indicator and a saved report, where the API reads the dead-letter queue from a position; elsewhere the head-of-queue loop stays.
- Earlier 2026-11-13: the navigation is in the toolbar, in Electron and in the browser, and the side navigation is gone; the developer mode shortcut takes Cmd as well as Ctrl; the Electron listeners for toggle-dev-mode and clear-all-data are removed.
- Earlier 2026-11-13: opening a session is one request and the session list is kept while the entity stays selected, with Refresh; sessions of a queue and a subscription in one component, a passive list, one session opened at a time, a state editor that never overwrites a changed state; a failed tree load says so; topic subscriptions load on open; a send retry carries only the form; CSV cells cannot start a formula; an unexpected continuous-resubmit error is a failure. 2026-11-12: the entity selection is cleared on every connection status; delete drains an entity only when the selection equals its count; Retry Failed and continuous resubmit never resend a possible duplicate; the purge confirmation names entity, topic, connection and count; a shortcut does nothing under another dialog.
- Earlier on 2026-11-12: every value in an API path goes through apiPath, encoded once; a name of . or .. recorded as a gap.
