# Web App history

What changed when in the project [[pages/services/web-app|Web App]] describes, newest first.

## 2026-11-14

- **Cancel scheduled messages of a topic.** Was: only a queue's scheduled messages could be cancelled, from the messages dialog. Is: the topic's More actions cancels by sequence number, and a scheduled send shows its number until closed. [[pages/services/web-app/features-entities-main]].
- **A deferred call runs under the progress dialog.** `web-app/src/app/features/messages/view-messages-dialog.component.ts#settleDeferred` opens the progress dialog that cannot be dismissed for resubmit, delete and dead-letter of deferred messages, so the messages dialog cannot be closed mid-call; Cancel aborts the call and warns that messages already processed may have been affected ([[pages/services/web-app/bulk-deferred-messages]]).
- **Deferred messages and Load more.** Was: a deferred message showed its chip and the note "This app cannot receive a deferred message."; each tab read one peek of the count asked from the head. Is: where the API declares `supportsDeferral`, the selection bar of the Active tab offers Resubmit deferred, Dead-letter deferred (with an optional reason and description) and Delete N deferred (name typed) for the deferred messages of the selection only, and says what it leaves out; where it declares `supportsPeekFromSequenceNumber`, a full page on the Active or Dead Letter tab offers Load more from the last sequence number + 1 ([[pages/services/web-app/bulk-deferred-messages]]).

- **Messages list, the filtered and empty states.** Was: a separate bar above the list said "Showing X of Y messages • quick search active • N advanced filters (AND)" with its own Clear all, and only for a search or an advanced condition; the no-match and empty titles were paragraphs; the rows were `div`s. Is: "Showing X of Y messages" at the end of the Select All row of each tab, also for Show = Scheduled and above the no-match state; Clear all only in the no-match state; the titles are h2; the rows are `li` in a `ul`. The entity form hints have specs.

- **Send with a new message ID.** The option is on the messages dialog's dead-letter and transfer tabs (single and bulk resubmit), the move dialog, which reads the chosen target with `getQueue`, the automatic resubmit dialog on start and retry, and the results dialog's Retry; it shows when the opener knows the target detects duplicates or after a duplicate refusal. The results dialog lists the new ids, "At least N unselected messages had their delivery count raised by one." and, as an alert, the unselected messages sent to the dead-letter queue (`web-app/src/app/core/services/bulk-operations.service.ts#NEW_MESSAGE_ID_OPTION`). [[pages/services/web-app/bulk-new-message-id]].

How the run reads, sends and completes is unchanged. Pinned by `web-app/src/app/app.spec.ts#while a resubmit runs, the bell carries the spinner and the percent, is named by the run, and opens the run card with Open, Pause and Stop on the environment and the connection`, `web-app/src/app/features/messages/continuous-resubmit-dialog.component.spec.ts#the dead-letter reason is chosen from "Any reason" and the named reasons the artboard draws, or typed under Other; the run takes a message whose reason equals it`, `web-app/src/app/features/entities/entity-details.component.spec.ts#a subscription's Active card reads`.
